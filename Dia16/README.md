Advent16


En este desafío, los renos parten desde la casilla “S” mirando al Este y deben llegar a la casilla “E”. Para avanzar, pagan 1 punto por cada casilla recorrida. No obstante, no pueden pasar a través de las paredes (“#”), lo cual restringe sus movimientos. Además, cada giro de 90 grados cuesta 1000 puntos, por lo que deben evitar giros innecesarios. El objetivo consiste en encontrar la ruta óptima que minimice la puntuación final. Por consiguiente, cada decisión de giro o avance influye drásticamente en el marcador. Al final, triunfa el reno que alcance “E” con la menor puntuación acumulada.

Este problema nos pareció muy divertido ya que era un problema claramente para grafos. Primero se planteó utilizar programación dinámica (no hay subproblemas que se repitan de forma acotada y reutilizable, como en DP), también se planteó usar una tabla hash para memorizar estados (ya que podemos representar la posición y dirección directamente en índices de un arreglo bidimensional o tridimensional). Pero esas opciones fueron descartadas ante la aparición del grafo ya que, se buscaba la ruta de menos coste en un entorno de cuadrícula y por ello, cada posición se podía ver como un nodo y cada avance o giro era una arista con diferente valor. 

Este programa lo interpretamos como una búsqueda de camino mínimo en un grafo implícito, donde cada nodo se asocia con una posición (𝑥,𝑦)(x,y) del laberinto junto con la dirección actual (definida por dirXdirX y dirYdirY). En este “grafo”, las aristas son las acciones posibles desde cada estado, avanzar en la dirección actual (con coste 1) o girar 90° y luego avanzar (con coste 1001). Para explorar estos estados, el código usa una cola de prioridad que siempre selecciona el nodo con el menor coste acumulado. Cada vez que se extrae un nodo de la cola, se generan sus “vecinos” (los estados obtenidos al avanzar o girar), y se les asigna un nuevo coste. Si un vecino aún no ha sido visitado, o se alcanza con un menor coste que antes, se añade a la cola. De este modo, cuando finalmente se extrae el estado que coincide con la posición de destino (“E”), su coste acumulado representa el camino de coste mínimo en el grafo que modela el laberinto.

Durante la realización del código surgieron inconvenientes ya que se salía de los límites por acceder a posiciones inválidas del vector ya que no validábamos que las coordenadas estuviésen dentro de los límites de este. Además, durante el planteamiento contábamos el giro como 1000 ya que se nos olvidaba considerar que al girar avanzaba y eso ya era 1001, esto nos generó una gran cantidad de resultados erróneos que nos costó corregir.

Realizando este código hemos aprendido a en qué tipo de problemas debemos usar grafos y a como plantearlos y adecuarlos correctamente siguiendo el enunciado. Además, nos generó una gran satisfacción completarlo ya que se nos hizo largo y tedioso al final debido a pequeños errores como el de contar el giro que nos costó detectar.

Para compilar este código debemos tener el input16.txt en la misma carpeta que el Advent16.cpp y compilarlo usando g++ -o Advent16 Advent16.cpp y después se debe usar ./Advent16 para comprobar el resultado.
